# 序付 · XUPAY

面向客户的订阅服务工作台与独立运营控制台。参考现有站点的业务功能，重新设计品牌、布局、颜色与文案。客户和管理员均使用左侧菜单。

技术栈沿用 Space/HUIXU：Vue 3 + TypeScript + Vite + Tailwind + Lucide，Go 1.25+ / net/http / ServeMux，PostgreSQL / pgx。提链协议在 Go 服务端实现，参考脚本存放于 `runtime/generator.py`，已移除其写死的默认代理凭据。

## 当前交付范围

- 客户：登录注册、工作台、Session 自动识别账号、订阅方案草稿、代理生成结账链接、横向订单进度、会员中心、资金账户、充值申请、兑换码入账、资金流水、API 密钥、接入文档、邀请关系、个人资料及改密。
- Session 检查与报价支持超时提示、手动重试和取消旧请求；页面停留后会话到期会阻止提交，会员或专属单价变更后会更新报价。
- 运营：经营概览、支付全监控、按日/周/月/年及客户财务报表、CSV 导出（防公式注入）、账户权限与批量单价、余额增减、充值审核、兑换码批量导出 TXT/停用/删除、套餐定价与会员等级、风控事件与配置、IP 限制、代理资源/测试、队列调度、公告与定时发布、操作审计、站点设置。
- 公告在登录页及工作台自动向左滚动。后台可控制展示范围、内容、排序和有效时间。
- 资金使用整数分。调账、兑换、审核使用事务与行锁，防止并发重复入账。账本与审计记录保留。
- 平台访问、订单、登录、兑换均有限流；客户/API 密钥不能访问后台接口，后台 JS 文件也要求管理员登录。
- 提链队列支持全局/客户/代理容量、FIFO、租约、延时重试、暂停及结果不明转人工核实。无可用代理时等待，不消耗重试次数、不直连。站内付款使用独立并发限制，并持续占用本订单的同一代理容量，直至本轮付款结束。
- 会员默认六档，按成功订单实际结算服务费（扣除退费）自动升级；充值、兑换和调账不计入成长。后台可配置门槛/折扣、临时或长期指定等级；到期恢复自动等级，专属单价优先，历史订单锁价。
- `/docs` 提供 13 个客户 API 操作（12 个路径）的字段、鉴权、错误及示例，`/api/openapi.json` 可下载 OpenAPI 3.1。网页与 API 使用同一会员、报价及权限规则。

## 付款与结算

新订阅的提链、付款、生效与续费设置采用用户附件 cs-live-source 的完整服务端流程。每单固定一个代理出口 IP，后台正式账单池随机抽取一份并固定加密副本。详细顺序、恢复与适配差异见 [订阅流程](docs/subscription-protocol.md)。后台订阅流程设置同时控制新建独立“结账链接”订单：后台 payment.checkout_types 为每个套餐分别配置长短链，两套流程及两个页面共用，受理时固定到本单。默认 Pro 5x/20x 长链、Team 标准/高级短链，Plus/Go 预设短链（尚未上架）。旧流程按 generator.py 的 long/short 分支用系统 curl 提链；新流程按本单类型调用 cs-live CreateCheckout。独立提链不付款；独立续费管理保持原实现。

订阅受理时冻结服务费，权威扣款结果与账本同事务幂等结算；明确未付款/拒付解冻，未知付款保留冻结。付款、生效、续费分别记录，后两步失败不抹掉已付款。恢复接续原交易，不重新建单或再次确认扣款。

银行卡及 CVV 不持久化，客户接口不返回账单、内部调用、动态令牌或订阅结账链接。管理员支付全监控保留阶段、诊断及实际链接历史。额外验证可能需要人工处理，未实现远程交互验证；本轮未进行真实扣款或真实取消。

## 全局代理与代理检测

Windows 本地使用 `scripts/start-local.ps1` 时，会读取已开启的系统 HTTP 代理作为外层连接：本机代理 → 后台选定的地区／全局代理 → 目标服务。最终出口仍由后台代理决定。可用进程变量 `XUPAY_LOCAL_PROXY=http://127.0.0.1:端口` 显式指定，或设置为 `off` 禁用；只接受本机回环 HTTP 代理，失败不直连。正式服务器直接启动应用／Docker 时默认不启用这层，也不会自动继承 HTTP_PROXY/HTTPS_PROXY 替换后台代理。付款浏览器通过本机私有 CONNECT 通道复用同一外层连接策略。

运营控制台 → 代理管理：点击某行“设为全局”，或在添加/编辑时勾选“设为全局代理（独立续费管理）”。代理配置也可选择“续费全局代理”。全局只能有一条，选择与提链的“同地区优先代理”互不替代；已有配置不会自动选为全局代理。

订阅办理从提链、付款到生效、授权刷新、取消和复查均复用原订单代理会话，出口漂移或会话失效即停。独立续费管理（包括从该工具接续）使用全局代理，每轮固定同一通道；未设置、停用或容量满时等待。

保留“连通测试”，新增“测试评分”和“OpenAI 测试”。后两者由后台队列执行，关闭窗口不终止，列表保留最新结果和时间。质量评分由出口连通（30）、连续两次连接成功（20）、响应速度（20）和 OpenAI 可达（30）组成，满分 100，分 A/B/C/D/F；不是 IP 信誉或风险分，也不保证具体账号业务成功。OpenAI 无密钥探测返回 401 表示目标可达；429、Cloudflare 验证与普通失败分开显示。动态代理出口变化只作说明、不扣分；旧评分提示重新测试。网络失败区分代理隧道、TLS、目标响应和读取阶段，显示固定脱敏原因，不返回原始网络错误或代理凭据。测试不登录账号、不付款或取消订阅，网页只获得脱敏结果。

## 使用结账准备

1. 运营控制台 → 代理管理：添加代理，支持 `host:port:user:password`（默认 HTTP）、HTTP/HTTPS/SOCKS5/SOCKS5H；选择对应的订阅地区（菲律宾、美国、日本、新加坡、埃及、土耳其、英国），测试出口 IP、国家、延迟。
2. 任务自动匹配同订阅地区的代理池。代理配置可指定同地区优先代理，停用或占满时使用同地区其他代理；没有空闲代理则排队，不跨地区或直连。队列配置可调整并发、重试间隔和默认订阅地区。订阅地区必须与实际代理出口相符；后台“订阅流程配置 → 套餐结账链接”可人工设置每个套餐的长链/短链，新旧流程均使用该规则。两个前台页面共用流程配置，受理时固定本单策略。
3. 单独提链进入“结账链接”，粘贴含 sessionToken 或受支持会话 Cookie 的完整 Session（旧流程也接受有效 AT-only），选择套餐与地区，点击“生成结账链接”。
4. 详情自动刷新；成功后可复制最终链接或打开付款页。打开上游付款页会使用客户浏览器的网络，本轮后台代理仅负责提链。
5. 无代理/容量不足时排队；已知安全失败默认重试 2 次、间隔 30 秒。上游可能已创建链接但响应不明时进入待核实，不重复提交。生成链接不表示付款成功。

## 订阅办理：一次提交

进入“订阅办理”，选择方案与地区、粘贴含 sessionToken 或受支持会话 Cookie 的完整 Session，再整行粘贴卡片信息。支持 `卡号----MM/YY----CVV`、`卡号----MM/YYYY----CVV`、`卡号|MM|YYYY|CVV`，自动校验卡号与有效期，只回显尾号和有效期摘要；卡片输入采用禁用自动填充的文本区域，不再使用容易被密码管理器误填的有效年/密码框。默认不勾选“保留自动续费”；提交后服务端连续完成提链、实时税费计算、自动付款和结果核实，再查询/关闭续费。勾选保留则付款成功后跳过取消。无需额外金额上限输入或中途报价确认。

订阅订单不向客户返回结账 URL、上游接口、原始响应或授权令牌；管理员仅在支付全监控详情查看实际链接历史及脱敏诊断。客户固定显示七步：提交申请 → 排队准备 → 办理准备 → 订阅付款 → 订阅生效 → 取消自动续费 → 办理完成。独立“结账链接”工具仅保留提链、复制链接和打开官方付款页，不启动站内付款。其四步进度在链接生成时全部完成，已生成的 link 订单不占用未完成订单限额。

运营控制台 → 站点设置 → US 账单资料已改为列表，支持新增、编辑、删除、启停、搜索和筛选；新增无需订阅邮箱，资料使用服务端生成的独立标识。管理员“随机测试”仅抽取已启用的测试资料，不创建订单、不付款。订阅付款从“已启用＋正式资料＋字段完整”的记录中均匀随机选择，不再按订阅邮箱绑定。每单选择一次，加密保存资料副本；重复提交、原订单重试和后台编辑/删除资料不会让在途订单换地址。停用及测试资料不进入新订单的付款池；无可用资料在提链、冻结前拦截。资料由运营配置，不生成虚构姓名/地址、不按税率选择地区。

连续订阅卡资料只保留本次内存，默认最长等提链 600 秒；进程重启后不会凭空恢复卡号或重放扣款。已付款成功但关闭续费最终失败时，订单显示“订阅成功，取消自动续费失败”，并在续费步骤显示警示；不会显示为整单待核实或全流程完成。可在续费管理粘贴同一账号对应空间的新 Session 免费继续，完成后原订单同步显示已关闭。付款结果未知仍为待核实，不允许另起付款。新协议生效/取消各最多查询 5 次、间隔 2 秒，沿用附件；旧续费 worker 的间隔和次数配置只影响兼容路径。平台取消最多发送一次。

## 独立关闭自动续费

客户工作台 → 续费管理：粘贴有效 Session，自动识别账号，确认后点击“关闭自动续费”。无需先下单、提供银行卡或账单资料，也不冻结或收取服务费。后台异步处理，页面显示提交申请 → 检查订阅 → 关闭核实 → 处理完成，并保存独立处理记录；原订阅办理的续费记录继续保留。

状态区分已关闭、无需关闭（没有需续费的有效订阅）和待核实。只有查询确认续费关闭才完成；取消响应 200 不算成功。待核实时重新提供有效 Session 继续原任务，保留原取消标记，未知写入不会重复发送。订阅付款成功、取消续费已停止的订单可以接续到独立任务；按所属客户与账号空间校验，转移取消标记，原 worker 不再执行。历史未保留空间指纹且从未提交取消的记录允许同客户、同邮箱以新授权接续；历史已提交但无法校验空间的记录由运营核实，不自动重发。任务重启恢复、同账号去重和订阅办理互斥均由数据库保证。

独立续费与旧订阅续费 worker 共用总并发、核实间隔与次数配置（默认 2 / 30 秒 / 10 次），独立任务另受单客户并发限制。新订阅使用附件查询顺序和订单固定代理；本菜单的独立任务使用全局代理，未配置、停用或容量占满时等待，不直连。Session 只保留加密的最小授权，结束或到期清除，最长 24 小时。浏览器只获得业务状态、时间与记录，不获得核心地址、请求或响应。

本次通过模拟上游、隔离 PostgreSQL 和浏览器检查，未向真实账号提交取消请求。

## 单独提链后的站内付款

旧订单可继续使用原付款准备、报价确认及结果核实。新建 link 订单仅提链，不能进入站内付款；新订阅一次授权后服务端连续办理，无需中途确认。后台付款配置控制启停、并发及超时，旧浏览器专用配置不改变新协议的内部查询顺序。

## Windows 本地启动

仅对独立开发环境使用以下启动方式；已迁移的本机旧副本不得启动。需要 Go 1.25+、Node 22+、PostgreSQL 18 工具及 Chromium。Windows 默认使用已安装的 Google Chrome，可通过 PAYMENT_CHROME_PATH 指定；无 Chrome 时在 runtime 目录执行 npx playwright install chromium。运行：

```powershell
./scripts/start-local.ps1
```

应用 `http://127.0.0.1:18860`，后台 `http://127.0.0.1:18860/#/admin`。独立 PostgreSQL 在 `127.0.0.1:18862`，数据位于 `.local/postgres`，不会启动或改动 Space/HUIXU。

首次启动生成唯一管理员密码和加密密钥，登录信息见 `.local/access.md`，环境变量在 `.env`。这两处已被 Git 忽略。初始账号 `admin@xupay.local`，初始真实业务数据为零；测试数据使用独立 schema 并自动清理。

停止：`./scripts/stop-local.ps1`。附加 `-WithDatabase` 才停止本项目独立数据库。重建前先停止本项目，启动脚本遇到被占端口会拒绝覆盖现有进程。

## Docker 部署

提供独立 `compose.yml`（xufu-app / xufu-postgres），对外端口默认 5496，PostgreSQL 18 使用独立数据卷且不暴露宿主端口。仓库为 `yigerende/xufu`，正式目录 `/opt/1panel/apps/xufu`。首次迁移本地数据和配置，之后只更新代码和应用镜像，保留生产数据库、`.env` 和主密钥。详细首次迁移、空闲检查、备份与更新步骤见 [部署说明](docs/deployment.md)。

更多边界见 `docs/security-and-payment.md` 和 `docs/implementation.md`。

## 账户页面与入口

个人设置采用独立账户概览：可用/冻结金额、全部/完成/待完成订单和实际服务消费，会员成长进度，以及最近 200 笔订单的状态/方案筛选。称呼和密码分别在弹窗修改，订单详情复用现有进度接口。统计来自全量后端聚合，不以当前筛选页计算总数。

API 文档、运营控制台、客户工作台入口使用新标签页（浏览器决定窗口形式），保留原页面，并设置 noopener noreferrer。

付款准备不提供手动取消功能；网页按钮及网页/API付款取消接口均已移除。普通撤回方案接口也不能停止订阅办理或已有付款记录的订单。未提交付款的自动超时/失败仍按原规则解冻服务费。
