# 支付链条与固定代理会话

运营控制台 → 支付全监控 → 订单详情 → 完整支付链条。

记录受理及资料校验、排队、服务费冻结、分配网络、提链、代理会话检查、打开付款页、账单填写、金额税费、提交付款、结果核实、费用结算或解冻、取消或保留续费、结束。每项带时间、状态、执行耗时和轮次；重建原因及等待重试可追溯。页面15秒刷新，历史订单保留原业务记录，不补造新阶段。

管理员可区分出口地区查询、创建结账单、结账初始化、登录态及账号/订阅查询。出口查询200不代表创建结账单成功。旧curl传输保留经白名单处理的请求编号和网关编号；仅上游明确返回挑战响应头时显示“上游要求安全验证”，不凭403猜测。Cookie、完整响应头和正文不投影。

管理接口只能由管理员访问。页面只消费本站保存的白名单记录；付款核心请求在服务端执行，核心接口地址、凭据、原始报文、完整卡号和账单副本不投影至任何订单接口。管理员详情会按授权单独返回最终结账链接，客户订阅订单接口不返回。

## 结账链接历史

“完整支付链条”中展示“生成的结账链接”，按轮次显示全文、生成时间与复制按钮。每次实际提链完成时加密留存，重建和付款完成不会覆盖原链接；付款状态继续以原流程为准，查看记录不会重新付款。HTTP部署也支持复制，不会自动访问上游链接。

旧订单仅保留升级时尚在库的链接，生成时间未知时注明“历史保留链接 · 生成时间未记录”。没有生成或已被清理的链接无法恢复；历史链接不代表仍可付款。

## 代理与兼容重建

订单按订阅地区选择代理。IPRoyal geo.iproyal.com 每单创建独立 session，默认 lifetime=1h；已配置的国家和有效寿命保留。全单复用加密保存的端点。旧提链保留原脚本首次地区查询；后续不比较出口IP。Windows 可经系统外层代理连接供应商，生产默认直接连接供应商；无可用代理禁止直连上游。

新旧提链及订阅按用户2026-10-30要求取消出口一致性检查，保留原代理绑定、有效期和任务租约。程序不会主动换代理，也不检测供应商是否改变出口；到期或租约失效仍停止。以下重建配置只影响旧订单的兼容路径。

后台付款配置的“付款前网络会话最多重建次数”默认为2，可设置0～5；0关闭自动重建。只有确认尚未提交扣款的会话失效或出口变化允许重新排队提链。原账单、副本、冻结费用保留，不重复冻结。普通网络安全重试仍按队列重试间隔执行。

已成功、已提交后连接中断、结果未知、需额外验证均不会自动重新扣款；恢复原交易，不重新确认扣款；新协议可能继续原交易待批准、生效和续费动作。原代理会话失效时停止核实并保留待核实，不换出口重付。付款成功后的取消续费失败，仍是“订阅成功，取消自动续费失败”。订阅办理的付款后查询、刷新及取消复用原订单代理会话；独立续费管理继续使用后台全局代理。

## 验证

使用隔离 PostgreSQL、模拟支付运行时及真实 Chromium 的本机模拟网关验证代理路由、重建上限、费用幂等、未知付款保护、权限与脱敏。测试不提交真实银行卡付款或真实续费取消。页面源码公开仓库不属于网络报文隐藏的保证范围。
