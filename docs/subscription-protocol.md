# cs-live 订阅流程接入

新建 `workflow=subscription` 订单的提链与付款统一调用用户提供的 `cs-live-source.zip` 内 `PaymentClient.Pay`；生效核实、取消续费及原交易恢复也采用该包实现。旧订阅继续兼容原处理路径，独立“结账链接”和“续费管理”工具保留其既有实现。

附件 SHA-256：`55aba3b8dd30114574f482f4c762b88d86958cbd965d1e3716369d47049e3687`。单文件按原模块拆入 `internal/cslive/`，未导入命令行、文件检查点存储及交互式 payment-action。`adapter.go` 连接同步检查点、进度、诊断及请求前订单检查。

## cs-live-source 完整流程

1. 校验 Session、银行卡、账单、地区、套餐、代理，建立交易上下文和可恢复检查点。付款需要 accessToken 与 sessionToken。
2. 首页 → 提链前刷新 Session → 核对账号 → 当前订阅基线。源码在刷新返回 session_expired 且原 AT 存在时允许继续在线核对原 AT，其他刷新错误停止；账号查询 401 时刷新重查。
3. 无冲突订阅时初始化支付上下文并创建一次 Checkout。已有有效订阅一般停止；明确支持的 Plus → Pro 5X 进入升级分支，使用差价估算、付款方式绑定和订阅更新，不新建 Checkout。
4. 按实际返回的 Hosted/Custom 模式及结账标识选择付款分支。Hosted 读取真实长链接、初始化付款页并更新账单税费；Custom 读取税费及原结账上下文。得到实时金额/币种后调用授权回调。
5. 创建付款方式或确认令牌，在不可安全重放的请求前同步保存检查点，提交付款并查询原交易。区分已扣款、未扣款、待处理、仅授权、需要额外验证；必要的原结账批准属于原交易。
6. 已扣款先保存资金结果，再核实订阅生效及套餐。最多查询 5 次、间隔 2 秒；遇 401 刷新后重查。失败不能抹掉已付款。
7. 保留续费则完成；默认取消时再次主动刷新、查询续费状态，已关闭直接完成，否则提交取消并最多查询 5 次、间隔 2 秒确认关闭。附件在特定瞬时失败且查询仍开启时允许第二次取消提交。
8. Recover 校验原检查点、查询原付款并继续生效/续费核实，不重新建单或再次确认付款；Custom 原交易可能继续待批准动作。额外验证可能需要人工处理，不视为成功。

## xufu 完整流程

| 客户固定步骤 | 服务端行为 |
| --- | --- |
| 提交申请 | 校验账号、方案、地区、完整 Session、卡片；幂等受理及同账号互斥；后台正式账单池均匀随机抽一份，保存加密副本，冻结服务费。 |
| 排队准备 | 原持久队列与容量限制；卡片只在内存等待，无对应地区代理则排队，重启不会恢复卡片或重付。 |
| 办理准备 | 绑定订单代理会话及出口，在一个 Pay 调用中按附件刷新授权、核对账号、提链及税费。 |
| 订阅付款 | 附件 Hosted/Custom/升级分支；同步加密检查点与提交标记，权威付款结果和服务费幂等结算。 |
| 订阅生效 | 附件查询与刷新时序；付款与生效状态分别保存。 |
| 取消自动续费 | 默认刷新、查询、提交、复查；保留时固定标题不变，下方显示“已选择保留”。 |
| 办理完成 | 生效及所选续费设置都确认才完成；后续异常保留付款成功，提示待核实。 |

## 保留规则与适配差异

- 每单一个出口 IP：提链、付款、恢复、生效、刷新、取消、复查均通过原订单私有 CONNECT 桥及同一代理会话。每次 HTTP 尝试前检查执行/容量租约、资源启停与有效期、探测出口；首次核对国家，漂移即停。新流程不换会话重新提链，不直连兜底。独立续费工具仍用全局代理。
- 每单一份随机正式账单：只选 enabled=true、test_only=false 且字段完整的后台资料；后续编辑、删除和恢复不重新抽取，不编造地址或按税率选地区。
- 保留 xufu 账号、余额、冻结、账本、队列与权限。未知付款保留冻结，仅恢复原交易；明确未付款解冻，已扣款只结算一次。恢复可补录原实收，不重复结算；升级估算和实收分别记录，可为零。
- 取消最多提交一次：保留 xufu 持久 cancel_started 和请求前拦截，比附件取消重试更严格；网络重试、恢复和接续不能清零。
- 套餐映射 pro→pro20x、team_premium→team5x，其余支持套餐直接映射。普通/高级席位分别传入，团队名称使用客户输入。默认请求 Hosted，实际分支尊重上游返回。
- 新订阅必须有刷新凭据，受支持分段 Cookie 可组装为 sessionToken；AT 过期但刷新凭据期限有效可进入服务端刷新。最小授权与检查点加密保留最长 24 小时；完整成功或明确失败清理，待核实保留至到期。PAN/CVV 不进入检查点/数据库。
- 新增 subscription_protocol 表，不把旧单伪装成新协议。新订阅在 Go 内运行，最低 Go 1.25；旧单保留 Chromium 兼容。新订阅开关不依赖 Node/Chrome 探测。
- 同步保存实际返回链接供管理员排查；未取得的链接不拼造。适配不增加创建 Checkout 次数。

## 账单字段映射

附件 Billing 所需资料由现有后台字段完整提供，无需新增后台字段：

| 附件字段 | xufu 来源 |
| --- | --- |
| Name | 正式账单 first_name + last_name |
| Line1 / City / State / PostalCode | 抽中账单的街道、城市、州、邮编 |
| Country | 现有 US 账单池固定 US，与订阅地区独立 |
| Email | 本次订阅账号邮箱，不使用账单条目的历史邮箱 |

附件当前不要求电话号码或地址第二行。后台校验比附件更严格：美国州代码、5 位或 ZIP+4 邮编、姓名/城市/街道完整；无合格资料不受理、不冻结或提链。字段齐全不代表真实支付一定通过。

## 客户隐私与后台监控

客户浏览器只提交本站业务请求和轮询业务状态，不执行上游核心调用。客户网页及 API key 接口不返回订阅结账链接、检查点、核心地址、报文、平台代理凭据、刷新令牌或完整账单。本人输入的 Session 和卡片仍会出现在本人提交请求中，不能对此隐藏。

支付全监控记录受理、排队、费用、网络、刷新、账号、提链、税费、付款、生效、续费、最终结果，以及可用的 HTTP 状态、请求关联编号、尝试次数、网络阶段耗时和白名单诊断码。实际结账链接加密进入管理员历史，页面不自动访问链接。原始报文、任意错误文本、PAN/CVV 和授权凭据不进入监控输出。

常规 HTTP 诊断有界异步落库，溢出/保存失败有汇总日志；关键资金及终态记录与业务事务一致。历史订单不伪造新记录。
