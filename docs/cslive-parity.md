## 原包代码核对

- 原包业务库的81个模块及所有声明均已核对存在；455个函数、56个常量、43个变量、73个类型与原包 AST 一致。
- 另外 4 个函数差异分别是：`prepareCheckout` 留存上游真实结账链接；`executeFlow` 留存 Hosted 最终链接；`transport_Transport.Request` 在每次请求前增加原订单 IP/租约检查；`transport_Transport.observe` 对原包已精确识别的“尚无订阅”响应保留 HTTP404 并标注业务原因。`transport_Transport` 增加对应回调字段。这些差异用于用户要求的后台监控和整单固定 IP，不改付款请求分支。
- 官方验证页 HTML 和 JS 逐字一致（忽略文件结尾换行）。服务端运行器触发原页面初始按钮；没有替换 `retrievePaymentIntent`、身份/状态检查或 `handleNextAction`。
- 单请求超时 45 秒、每次 Pay/Recover 预算 240 秒取自原包 `DefaultConfig`。外层任务额外预留 SDK 的 10 分钟及后续恢复，不覆盖协议预算。

## 验证运行器与监控修复（2026-10-29）

- 浏览器并发资源共享尚在执行中的同单出口/租约检查，完成后不缓存检查结果；后续请求重新检查。不再在 IPC 主循环里逐个等待探测，避免后到资源在15秒等待窗口内被排队耗尽。原代理、原出口、关单/过期拦截保持。
- 原 SDK HTML/JS 文件不变；独立观察脚本仅在原调用前后报告固定阶段，不修改参数、返回值、异常或交易身份。冻结方法不可观察时仍执行原方法。记录加载、上下文、预查、SDK调用、回传、资源失败和30秒等待进展，不记录URL、token、响应正文或验证码。
- 加载原页面等待 `load`，避免后台遥测请求影响 `networkidle`；只自动点击原初始按钮，不模拟持卡人完成真实挑战。
- custom 链接按原包 `checkoutURL` 的规则从原结算单身份显示；Hosted 保留实际返回的完整长链。新单加密保存，旧单可从仍保留的检查点只读恢复展示，不伪造历史生成时间、不重新提链。仅管理员可见。
- 自动任务尚在运行时显示自动验证/核实，不显示手动启动按钮。原包精确识别的无订阅404显示正常查询结果；其他404仍按错误处理。历史审计不改写。

离线回归已复现旧串行检查在并发资源下耗尽预算；此前真实订单缺少内部阶段记录，因此不能认定它必然只有这一处原因。模拟成功不等于真实卡付款成功，新单需结合新增监控验证。

## 顺序和分支

| 环节 | 原包行为 | xufu 对应行为 |
| --- | --- | --- |
| 授权与账号 | 首页、提链前刷新、账号身份核对、订阅基线；原包的刷新失败/401分支 | 调用同一 Pay 实现及同步检查点 |
| 提链 | 独立入口默认 Hosted 请求偏好，实际按响应模式与 `cs_live_` / `oaics_` 分支 | 同样请求 Hosted，尊重实际响应；不另造链接 |
| 账单和税费 | 所传 Billing → Hosted 更新税费或 Custom 税费查询 | 从后台启用、正式、完整资料随机抽取，之后复用本单加密副本；此为用户指定差异 |
| 付款 | Hosted、Custom 或受支持的订阅升级；同步保存后提交；原交易批准和结果查询 | 相同函数与参数语义；网站报价授权回调衔接已提交的办理申请，不增加人工确认 |
| 待验证 | 配置 TLS 的 CLI 分支打开短时入口，用户打开原页面并点击按钮；SDK 完成后 Recover | 同一订单任务自动打开服务端原页面并触发初始按钮，之后 Recover；这是全自动网站对 CLI 交接的适配，不声称原 CLI 无人工入口 |
| 原交易恢复 | Recover 不重建 Checkout、不重新提交银行卡确认；可继续原交易批准 | 相同 Recover；仍待验证则自动执行一轮 SDK 并再次 Recover，不循环重试挑战 |
| 付款成功 | 权威付款结果后核实套餐生效；最多5次，间隔2秒；401刷新后重查 | 相同实现；SDK回调本身不结算服务费、不标记已付款 |
| 取消续费 | 按所选 renewal 参数，先刷新、查询、按需取消并复查；特定瞬时失败允许有限重试 | 按用户的保留续费选项传参数，默认相当于原包 `--renewal cancel`；不再叠加旧单的一次发送限制 |
| 完成/异常 | 保留真实付款状态，不能把生效或续费失败当未扣款 | 同步本站订单、账本和七步投影；异常保留原交易，不重付 |
| 网络 | 按原包传入代理执行 | 所有步骤都绑定本单原代理和出口，逐次核对并禁止漂移/直连；此为用户指定差异 |

本站账号权限、资金冻结/结算、队列、幂等、监控、人工关单和用户七步显示由网站承接。独立提链工具、独立续费工具和历史旧协议订单继续使用各自兼容流程，本次全链条对照针对新协议订阅办理。

官方 SDK 可自动完成的验证无需点击后台按钮。上游真正要求持卡人交互时，原包也不能保证自动通过；本系统记录SDK结果或到期原因并保留待核实，不伪造验证成功。部署不批量重放已暂停历史订单。
