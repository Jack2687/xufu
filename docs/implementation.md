# 序付实现说明

更新于 2026-10-29。Vue 3 / TypeScript / Vite + Go 1.25+ / net/http + PostgreSQL / pgx。正式环境为 xufu 独立应用及数据库，端口 5496；本机旧 18860/18862 副本迁移后保持停止，不启动双队列。本轮为本地源码改造，尚未部署。

## 平台与资金

保留客户工作台、会员、钱包、充值/兑换/流水、API 密钥、独立提链及续费工具；运营包含支付全监控、财务、账户、定价、风控、代理/调度、账单池、公告及审计。

站内余额 R 使用整数分，上游金额采用对应币种最小单位，JPY 不除以 100。会员成长只计算成功订单服务费减关联退款，充值/兑换/调账不计成长；专属单价优先，订单锁价。冻结、解冻、付款和账本事务化且幂等。

## 新订阅

workflow=subscription 通过 cs-live-source 的完整 Pay 调用实现服务端提链与付款，Recover 接续原交易。模块位于 internal/cslive，适配位于 internal/platform/subscription_protocol*.go。完整流程见 [订阅协议](subscription-protocol.md)。

受理时验证刷新凭据、卡片和后台正式账单池，一次随机抽取并保存账单加密副本、冻结服务费；卡片只在内存，队列领取后由唯一 worker 使用。subscription_protocol 保存加密检查点、执行租约及期限，旧订单无此标记继续原路径。

每订单固定代理会话及出口，核心请求前检查租约、代理有效期及出口。新流程不自动换 IP 或重建 Checkout。实际取得的 Hosted URL 加密进入管理员链接历史，不拼造链接。

客户端固定七步：提交申请、排队准备、办理准备、订阅付款、订阅生效、取消自动续费、办理完成。保留续费仅改变第六步小字；客户网页与 API key 不返回核心调用、检查点或订阅结账链接。

待验证时同一任务自动运行原包官方 SDK，随后 Recover 核实原交易。已扣款先幂等结算，再核实订阅生效和续费。生效/取消采用附件最多 5 次、间隔 2 秒；取消按原包瞬时失败先查询、仍开启才有限重试。后续失败保留付款成功，恢复不再次确认扣款。缺少原代理、授权或检查点时不能凭空恢复。完整成功或明确失败清理授权，待核实最长保留 24 小时。

## 兼容与监控

独立结账链接按 payment.subscription_flow 在受理事务中选择执行器，并保存 checkout_runs.flow；历史提链默认 legacy。旧流程用系统 curl：long 为 iOS/Hosted 真实直返长链或 Stripe init，short 为 Web/Custom 官方短路由；两套新订单受理时从 payment.checkout_types 按 product_id 读取类型，保存到 checkout_runs.checkout_type；新流程将该类型传给 cs-live CreateCheckout，不挂付款检查点，不调用 Pay/Recover。两套流程使用逐套餐配置；新协议付款仍按实际返回模式执行，历史 auto 记录保留默认入口，均拒绝异单链接及缺失 URL，未知结果不重新创建。新 link 订单禁止站内付款；旧单的 Chromium 付款与旧恢复路径继续兼容。独立续费工具无需订单、账单或付款，使用全局代理，并可接续同账号待核实取消，提交标记不清零。

支付全监控记录白名单阶段、时间、结果、错误分类、HTTP 状态、请求关联编号、网络分段耗时与实际链接历史。详细信息仅管理员可见，原始报文、授权、卡片及完整账单不投影。异步诊断与关键资金记录的边界见 [授权与监控](session-and-payment-monitoring.md)。
