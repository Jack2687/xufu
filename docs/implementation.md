# 序付实施记录

更新于 2026-10-28。Vue 3 / TypeScript / Vite + Go net/http + PostgreSQL；当前运行范围为本地应用 18860 和独立数据库 18862。

## 平台

客户：登录注册、Session 识别、订阅草稿与代理提链、站内付款与横向进度、会员中心、钱包/充值申请/兑换/流水、API 密钥及文档、邀请关系和个人资料。

运营：总览、全订单监控、财务日周月年/用户统计、账户/批量单价/余额调整、充值审核、兑换码、套餐和会员规则、风控与配置、代理资源与调度、公告、审计及站点设置。客户与运营使用独立左侧菜单；文档/客户/运营入口在新标签打开。

## 会员与金额

平台余额单位 R，数据库按整数分；上游 amount 使用对应币种最小单位，JPY 不除以 100。默认 L1/L2/L3/L4/L5/L9，门槛 0/2000/5000/10000/20000/100000 R，服务费减免 0/5/10/15/20/80%。支持指定等级、期限、专属单价；专属单价优先，历史订单锁价。

成长只计算成功订单对应的服务费 charge 减关联 refund，每单最低零；充值、兑换、调账不计成长。付款结果与资金结算必须同一事务完成，不能将手工备注当作成功证据。

## 提链

`POST /api/orders` 或 `/api/v1/orders` 携带 `prepare=true` 原子创建订单及任务；默认 false 保持草稿兼容。AT/空间 ID 加密暂存，结束/取消后清除；不保存原始 Session。默认长链接，缺失真实返回 URL 时不猜测。

同任务固定使用同订阅地区的后台代理；全局/客户/代理容量由数据库协调，无代理等待且不消耗重试。已知安全失败按配置延时重试，提交结果不明则待核实。最终链接加密保留 30 分钟，提链成功仅为 awaiting_payment，不冻结或收取服务费。

## 付款

新增 `payment_runs`，每单一个当前 attempt；只存尾号、状态、金额、币种、过期时间、提交标记、加密链接及服务费结算状态。不持久化银行卡或 CVV。

客户接口为 `/orders/{id}/payment/prepare|confirm|check`，网页及 `/api/v1` 共用权限和业务逻辑。管理员只有独立的付款结果核实接口。公开文档共 13 个操作、12 个路径。

Go 将临时输入通过私有管道传给 Node/Playwright 运行时，官方结账页面自行获取实时参数、计算税费和发起付款；US 账单在后台生成。所有付款步骤使用默认机器网络，禁止继承提链代理池。输入与运行时原始异常不写日志。

状态流：preparing → quoted → submitting → succeeded；未知结果为 review，额外验证为 action_required；check 进入 checking，只查询、不重新确认付款。独立付款确认含税金额；订阅办理一次授权后自动继续，重复 confirm 不重发，异常金额不结算，成功和资金账本事务提交。取消/明确拒付解冻，未知结果冻结等待核实。

付款配置默认启用、总并发 2、每客户 1、准备 120 秒、报价确认 180 秒、结果等待 120 秒、准备每分钟 3 次。报价等待占用并发；满载返回 429，不把银行卡放到数据库排队。

## 范围与验证

已完成本地模拟上游全流程、Go/PostgreSQL、vet、TypeScript/Vite、浏览器权限和网络检查。真实默认网络验证仅覆盖官方页面初始化和账单税费刷新，没有真实扣款。订阅办理默认已接入取消续费，可选择保留；额外验证可能暂停流程，未实现远程交互验证。链上充值、邀请返利及独立续费工具未接入。

Dockerfile 已加入付款浏览器依赖，本轮未构建/运行 Docker，也未推送仓库或部署正式环境。详细验证证据见 `verification.md`。


## 订阅办理更新

workflow=subscription 的订单一次提交 Session/卡片/方案/地区/续费选择，不新增扣款上限输入。服务端自动衔接长链和付款，UI 六步进度；订单详情、列表和管理员详情都不返回其结账链接。客户端只能提交序付业务请求。US 账单读取后台按订阅邮箱保存的真实资料，支持所有州，不随机生成或按税率选择。缺失资料在提链和冻结前拦截；旧无邮箱模版不会复用到其他账号，税额以实时页面报价为准。

subscription_runs 保存续费所需的加密最小授权。付款成功后默认自动核实并关闭续费；保留续费不发取消请求。取消之前持久化单次提交标记，未知响应不重发，每 30 秒核实、默认最多 10 次。订阅最长准备等待默认 600 秒；这些配置在后台付款配置中调整。

付款准备不提供手动取消功能；网页按钮及网页/API付款取消接口均已移除。普通撤回方案接口也不能停止订阅办理或已有付款记录的订单。未提交付款的自动超时/失败仍按原规则解冻服务费。
