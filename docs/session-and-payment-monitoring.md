# 授权恢复与支付全监控

本次沿用现有长链提取、后台 Chromium 付款、随机正式账单选择与同订单固定网络。没有替换付款协议、模拟成功或新增自动重扣入口。

## 授权及付款后核实

- 用户原来的 Session 提交方式不变。有可用 sessionToken 或受支持的会话 Cookie 时，在提链前、付款成功后的核实阶段刷新授权，并验证邮箱、空间和有效期。
- 只有 AT 的 Session 仍可使用；无法凭空刷新。AT 失效且没有可用刷新凭据时，保留明确的授权失效结果。
- 仅加密保存最小授权字段，最长 24 小时；终态和到期清理。刷新轮转后的 Cookie 与 AT 必须在当前任务租约内保存，旧 worker 不能覆盖新任务。
- 提链前在线核对原账号，已有有效订阅或空间不符时停止新建结账。提链仍默认长链。
- 付款成功后独立核实订阅是否已生效、套餐是否匹配。保留自动续费的订单也核实生效，但绝不提交取消。
- 生效核实默认间隔 **5 秒**，最多 **12 次**；可在运营控制台的付款配置调整。网络请求耗时不计入间隔，实际总等待时间可能更长。
- 生效后按客户选择取消续费或保留。取消提交前持久记录提交标记；超时、刷新授权、重启、独立续费接续都不清零，未知结果只读核实。
- 已付款、已生效、已关闭续费分别记录。后两步异常保留已付款和服务费结算；不重新付款、不更换账单。套餐不符不得冒充生效。
- 提链及前置校验使用该订单的地区代理；付款复用同一固定会话；付款后授权刷新、生效核实和关闭续费均用后台全局代理，不回退直连。

## 管理员支付全监控

完整链条包含受理、排队、费用冻结、网络分配、刷新授权、账号核对、提链、页面、填资料、税费报价、付款提交、结果核实、实收证据、订阅生效、续费处理和最终结果。

每阶段保留时间、轮次、结果、耗时、错误分类；可用时增加响应状态、关联编号、域名解析/连接/握手/首字节时间、响应格式和白名单上游错误码。常规 HTTP 诊断经有界异步队列写入，队列溢出或存储失败会输出汇总告警；关键付款、资金和终态记录仍与业务事务一起提交。

真实付款证据只接受属于本订单结账会话的结果，最小证据加密保存。只有已捕获金额才能成为实收；仅授权未扣款不标记为付款成功。

客户接口不提供完整诊断；管理员页面只读取本站记录，不调用上游核心接口。管理员可见历史结账链接是用户明确要求的例外。接口路径、请求正文、AT、Cookie、代理密码、卡号/CVV、完整账单和原始响应均不返回监控接口。

历史订单不伪造订阅生效和诊断记录。离线与模拟测试不代表真实上游支付实测。
