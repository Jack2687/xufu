# 授权恢复与支付全监控

新建订阅使用用户提供的 cs-live-source 协议，提链、付款、生效和取消续费都在 Go 服务端完成。完整顺序和适配差异见 [订阅流程](subscription-protocol.md)。旧订单保留原 Chromium 兼容路径，独立提链及续费管理工具不改变实现。

## 授权及付款后核实

- 新订阅需要 accessToken 及 sessionToken 或受支持的会话 Cookie。仅 AT 的输入仍可用于独立提链，不能用于新的完整订阅办理。AT 过期但刷新凭据期限有效时可受理，在服务端刷新；格式检查不是在线登录验证。
- 按附件先访问首页、刷新 Session，再核对账号和已有订阅，之后创建 Checkout。附件在刷新返回 session_expired 且仍有原 AT 时允许在线核对原 AT；其他刷新错误停止。身份不匹配不能继续。
- 已扣款先保存付款成功与资金结算，再查询订阅是否生效、套餐是否匹配；遇 401 刷新后重查。生效最多查询 5 次、间隔 2 秒，网络耗时另计。
- 保留续费仍核实生效，随后完成。默认取消则再次主动刷新、查询续费状态、按需提交取消，最多查询 5 次、间隔 2 秒确认关闭。新协议不使用旧 worker 的 5 秒×12 次或 30 秒×10 次配置。
- xufu 保留最多一次取消提交的持久标记，拦截附件可能的第二次发送；超时、恢复、重新授权及独立续费接续不能清零。已提交后只能核实状态。
- 付款、订阅生效、续费设置分别记录，后两步异常保留已付款和服务费。恢复只接续原交易，不重新建单或再次确认银行卡付款；原 Custom 交易可继续待批准动作，因此不能将整个恢复接口称为纯只读。
- 最小授权及检查点加密保留最长 24 小时；完整成功或明确失败清理，待核实保留至到期。原始 Session JSON、PAN/CVV 不持久保存。保存检查当前执行租约，旧 worker 不能覆盖新任务。
- 新订阅全程复用订单代理会话。每次请求前检查租约、代理启停、有效期及出口；漂移、过期或绑定缺失时停止，不直连或自动换会话重付。独立续费工具仍使用后台全局代理。

## 管理员支付全监控

记录受理、排队、冻结、网络、授权刷新、账号核对、提链、账单税费、提交付款、结果核实、实收证据、订阅生效、续费和结束。每项包含阶段、时间、结果、耗时和安全原因。

有证据时显示 HTTP 状态、请求关联编号、请求尝试次数、连接就绪/请求写入/响应等待/首字节耗时、网络阶段及白名单上游错误码。原始路径只在服务端内存中用于分类，不落监控记录。常规 HTTP 诊断通过有界异步队列落库，溢出/保存失败有汇总日志；关键付款、资金及终态记录与业务事务提交。

实际取得的结账链接加密保存，仅管理员在支付全监控详情查看历史；页面不自动访问链接。客户与 API key 接口只返回业务状态，不返回这些链接或诊断。管理员也不能通过监控取得请求正文、AT、Cookie、代理密码、PAN/CVV、完整账单或原始响应。

实收证据必须匹配原交易，最小证据加密保存；仅授权不能算扣款。已成功订单后续补录实收证据不再次结算服务费。历史订单不伪造生效或诊断记录，模拟验证不代表真实付款实测。
